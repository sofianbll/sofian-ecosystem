# Skill routing

## Socle obligatoire du projet

| Skill / source | Rôle |
|---|---|
| Guide ultime 2026 | valeur, domaine, preuves, architecture, données, agents et évolution |
| `software-engineering-lifecycle` | méthode d’ingénierie et décisions proportionnées |
| `opencode-history` | historique canonique OpenCode/OpenChamber en lecture seule |
| `ourmem` | mémoire sémantique secondaire et ses limites |
| `obsidian` | lecture ciblée des vaults et conventions |
| `i-have-adhd` | rythme, état visible et prochaine action |
| `tdah-visual-responses` | structure visuelle et réduction de charge |

## Selon le workstream

| Situation | Skill à charger | Contre-indication |
|---|---|---|
| réconcilier tout le système personnel | `personal-system-reconciliation` | ne pas créer une architecture avant l’inventaire |
| reprendre un agent ou une session | `cross-agent-session-handoff` | ne pas utiliser un résumé comme état live |
| connecter des sources sans les copier | `personal-knowledge-migration` | ne pas importer dans Hermes par défaut |
| archiver ou déplacer des documents | `personal-filesystem-governance` | aucune mutation pendant un audit |
| lire Notion | `notion` | ne jamais écrire sans nouveau lot autorisé |
| lire ou analyser un DOCX | `docx` | ne pas modifier l’original historique |
| produire des citations vérifiables | `grounded-citations` | une URL ne remplace pas une preuve locale |
| adapter un workflow pour un agent | `canonical-workflow-agent-adapters` | réconcilier le canon d’abord |
| configurer Hermes | `hermes-agent` + docs officielles | docs officielles prioritaires |
| modifier une skill | `hermes-agent-skill-authoring` | seulement après procédure répétée et prouvée |

## Règle de capitalisation

Ne pas créer un router skill qui duplique cette page. Commencer par le protocole projet. Après plusieurs audits réels, patcher la skill générique uniquement avec les étapes réutilisables, testables et non spécifiques à un seul fichier.
