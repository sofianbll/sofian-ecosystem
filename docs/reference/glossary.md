# Glossaire

| Terme | Sens dans ce projet |
|---|---|
| Écosystème | gouvernance et relations entre domaines, capacités et systèmes ; pas une base unique |
| Domaine de vie | responsabilité durable qui existe sans outil ou projet actif |
| Capacité | ce qu’il faut savoir accomplir dans plusieurs situations |
| Système | frontière durable avec valeur, langage, état, règles, cycle de vie et risques |
| Module | responsabilité logique locale ; n’implique ni service ni OS |
| Projet | initiative temporaire visant un résultat |
| Workflow | trajet ordonné transformant une entrée en résultat observable |
| Routine | usage périodique de workflows et vues |
| Adapter | implémentation reliant un modèle ou workflow à un outil |
| Runtime | environnement d’exécution ; ne possède pas automatiquement le métier |
| Autorité | source dont l’état gagne pour un fait précis |
| Projection | copie, index, vue, résumé ou mémoire reconstruisible depuis une source |
| Claim | affirmation atomique avec provenance, temps et état de preuve |
| Audit | collecte et réconciliation read-only d’un périmètre borné |
| Workstream | unité documentaire d’audit ; pas une tâche opérationnelle |
| Besoin | résultat souhaité dans une situation, avant la solution |
| Idée | piste non validée comme besoin ou décision |
| Cible candidate | option d’architecture encore discutable |
| Cible acceptée | choix explicitement validé par Sofian |
| Roadmap | séquence de résultats et dépendances ; TaskNotes porte l’exécution |
| Canonisation | promotion explicite d’un contenu revu dans le corpus actif |
| Baseline | snapshot historique immuable, sans validation implicite |
| Contre-audit | vérification indépendante d’un rapport et de ses sources décisives |

## Distinctions à préserver

- besoin ≠ fonctionnalité ≠ tâche ;
- domaine ≠ Area ≠ système ;
- sous-domaine ≠ bounded context ≠ service ;
- système ≠ projet ≠ outil ;
- mémoire ≠ vérité métier ;
- documenté ≠ testé ≠ accepté ≠ opérationnel ;
- archive ≠ obsolète ;
- cible candidate ≠ décision.
