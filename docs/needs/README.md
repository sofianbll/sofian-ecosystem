# Besoins

## Principe

Un besoin décrit une situation et un résultat souhaité. Il n’est pas encore une fonctionnalité, un outil, une tâche ou un nouveau système.

```text
situation → résultat attendu → capacité
→ couverture actuelle → options de responsabilité
```

## Pipeline

1. capturer une idée ou un irritant ;
2. chercher un cas réel et sa conséquence ;
3. distinguer besoin, politique, contrainte et solution proposée ;
4. valider ou différer avec Sofian ;
5. mapper les capacités ;
6. seulement ensuite comparer les systèmes candidats.

## Statuts

- `idea` — piste non validée ;
- `observed` — appuyée par une situation réelle ;
- `validated` — résultat souhaité confirmé par Sofian ;
- `deferred` — utile mais hors priorité actuelle ;
- `rejected` — explicitement écarté avec raison.

## Règles

- un besoin peut traverser plusieurs systèmes ;
- chaque fait conserve une seule autorité ;
- une idée agentique n’est pas un besoin utilisateur ;
- un besoin important ne justifie pas automatiquement un nouvel OS ;
- les tâches de réalisation restent dans TaskNotes.
