# Workflows

Les workflows historiques de la fondation initiale sont archivés. Aucun n’est automatiquement promu comme workflow courant.

## Distinctions obligatoires

| Objet | Question |
|---|---|
| Processus de vie / métier | que se passe-t-il réellement ? |
| Parcours utilisateur | que voit et décide Sofian ? |
| Workflow canonique | quelles étapes, règles et sorties sont établies ? |
| Adapter agentique | comment Jarvis lit, propose, demande l’accord et vérifie ? |
| Implémentation | quels outils et contrats exécutent le workflow ? |
| Routine | quand et comment le workflow est déclenché dans le temps ? |

## Registre à reconstruire

- Capture ;
- Clarify ;
- Create Task / Project / Resource / Aspiration ;
- Engage ;
- Daily Start ;
- Daily Review ;
- Weekly Review ;
- Inbox Processing ;
- Mail to Task ;
- iOS Capture ;
- autres workflows retrouvés dans les sources.

Chaque nom reste séparé tant que sa version, son autorité et son état réel ne sont pas prouvés.

## Critère de fin

Un workflow actif possède déclencheur, acteur, entrée, décisions, étapes, sorties, exceptions, autorité par fait, permission de mutation, preuve visible et scénario réel. Une fixture seule ne prouve pas l’intégration.
